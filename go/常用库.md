### sync

#### sync.Map

并发版本Map

```go
//多go读少写时使用

m := &sync.Map{}

// 添加元素
m.Store(1, "one")
m.Store(2, "two")

// 获取元素
value, contains := m.Load(1)
if contains {
  fmt.Printf("%s\n", value.(string))
}

// 返回已存value，否则把指定的键值存储到map中
value, loaded := m.LoadOrStore(3, "three")
if !loaded {
  fmt.Printf("%s\n", value.(string))
}

// 迭代所有元素
m.Range(func(key, value interface{}) bool {
  fmt.Printf("%d: %s\n", key.(int), value.(string))
  return true
})
//

//删除
m.Delete(3)
```

#### sync.Mutex

互斥锁

不能同时访问

```go
mutex := &sync.Mutex{}
 
mutex.Lock()
// Update共享变量 (比如切片，结构体指针等)
mutex.Unlock()

//第一次被使用后，不能再对sync.Mutex进行复制。（sync包的所有原语都一样）。如果结构体具有同步原语字段，则必须通过指针传递它。
```

#### sync.RWMutex

读写互斥锁

允许使用RLock和RUnlock方法进行并发读取

**关键机制**

1. 读写锁优先级
   - **如果写锁正在等待（即 `Lock()` 已调用但未获取锁），新的读锁（`RLock()`）会被阻塞**，直到写锁完成
   - 避免**写锁饥饿**（Write Starvation），即写操作因持续有读操作而无法执行
2. 锁的互斥性
   - 多个 `RLock()` 可以**并发执行**（共享锁）。
   - Lock()是**独占锁**，会阻塞所有其他 **RLock()**和 **Lock()**



**写锁为独占锁**

**读锁为共享锁**



```go
mutex := &sync.RWMutex{}
 
mutex.Lock()
// Update 共享变量
mutex.Unlock()
 
mutex.RLock()
// Read 共享变量
mutex.RUnlock()

//sync.RWMutex允许至少一个读锁或一个写锁存在，而sync.Mutex允许一个读锁或一个写锁存在。
```



sync.Mutex与sync.RWMutex对比

```shell
# 通过基准测试来比较这几个方法的性能：

BenchmarkMutexLock-4       83497579         17.7 ns/op
BenchmarkRWMutexLock-4     35286374         44.3 ns/op
BenchmarkRWMutexRLock-4    89403342         15.3 ns/op

# 可以看到锁定/解锁sync.RWMutex读锁的速度比锁定/解锁sync.Mutex更快，另一方面，在sync.RWMutex上调用Lock()/ Unlock()是最慢的操作。

#总结：
#读锁：sync.RWMutex 比 sync.Mutex 更快
# sync.RWMutex上调用Lock()/ Unlock()是最慢的操作
# 多读少写用sync.RWMutex
```



#### sync.Pool

并发池，负责安全地保存一组对象。

```go
Get() interface{} //用来从并发池中取出元素。
Put(interface{}) //将一个对象加入并发池。

----------------------------------------
pool := &sync.Pool{}
 
pool.Put(NewConnection(1))
pool.Put(NewConnection(2))
pool.Put(NewConnection(3))
 
connection := pool.Get().(*Connection)
fmt.Printf("%d\n", connection.id)
connection = pool.Get().(*Connection)
fmt.Printf("%d\n", connection.id)
connection = pool.Get().(*Connection)
fmt.Printf("%d\n", connection.id)
```

创建者模式

```go
pool := &sync.Pool{
  New: func() interface{} {
    return NewConnection()
  },
}
 
connection := pool.Get().(*Connection)
//这样每次调用Get()时，将返回由在pool.New中指定的函数创建的对象
```

适用

1.重用共享的和长期存在的对象。数据库连接

2.优化内存分配

案例：

```go
//*****写入缓冲区并将结果持久保存到文件中的函数****//
//通过在不同的函数调用之间重用同一对象来重用为缓冲区分配的空间

func writeFile(pool *sync.Pool, filename string) error {
    buf := pool.Get().(*bytes.Buffer)
 
    defer pool.Put(buf)
    
    // Reset 缓存区，不然会连接上次调用时保存在缓存区里的字符串foo
    // 编程foofoo 以此类推
    buf.Reset()
    buf.WriteString("foo")
    return ioutil.WriteFile(filename, buf.Bytes(), 0644)
}

```

#### sync.Once

确保一个函数仅执行一次

```go
once := &sync.Once{}
for i := 0; i < 4; i++ {
    i := i
    go func() {
        once.Do(func() {
            fmt.Printf("first %d\n", i)
        })
    }()
}
//使用了Do(func ())方法来指定只能被调用一次的部分
```

#### sync.WaitGroup

线程组

```go
wg := &sync.WaitGroup{}
for i := 0; i < 8; i++ {
  wg.Add(1)  //增加wg的内部计数器
  go func() {
    // Do something
    wg.Done()  //减少wg的内部计数器
  }()
}
 
wg.Wait()  //等待上面的执行完毕之后再往下执行
```
